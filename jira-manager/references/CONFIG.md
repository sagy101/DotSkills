# Configuration Reference

The `.jira.json` file lives in the project root and configures the jira-manager skill for that project.

## Full schema

```json
{
  "jira_url": "https://mycompany.atlassian.net",
  "project_key": "API",
  "credentials": {
    "username_env": "JIRA_EMAIL",
    "token_env": "JIRA_TOKEN"
  },
  "env_file": ".env",
  "manifest_path": ".jira-manifest.json",
  "source_dir": ".",
  "git_remote": "auto",
  "git_branch": "main",
  "estimation_pattern": "Estimation:\\s*([\\d.]+)\\s*days?",
  "field_mappings": {
    "epic_link": "customfield_10632",
    "story_points": "customfield_10133"
  },
  "issue_types": {
    "epic": "10000",
    "story": "28",
    "subtask": "10102",
    "bug": "10004",
    "task": "10001"
  }
}
```

## Field descriptions

| Field | Required | Default | Description |
|---|---|---|---|
| `jira_url` | Yes | — | Base URL of your Jira Cloud instance (no trailing slash) |
| `project_key` | Yes | — | Jira project key (e.g. `API`, `PROJ`) |
| `credentials.username_env` | No | `"JIRA_EMAIL"` | Environment variable name for the Atlassian username/email |
| `credentials.token_env` | No | `"JIRA_TOKEN"` | Environment variable name for the API token |
| `env_file` | No | `null` | Optional path to a `.env` file to load credentials from |
| `manifest_path` | No | `".jira-manifest.json"` | Where to store the ticket manifest file |
| `source_dir` | No | `"."` | Directory containing ticket source files, relative to project root |
| `git_remote` | No | `"auto"` | Git remote URL for link rewriting. `"auto"` resolves via `git remote get-url origin` |
| `git_branch` | No | `"main"` | Git branch for link rewriting. `"auto"` resolves via `git branch --show-current` |
| `estimation_pattern` | No | `"Estimation:\\s*([\\d.]+)\\s*days?"` | Regex to extract story points from description text |
| `field_mappings` | No | `{}` | Maps friendly names to Jira custom field IDs. Run `discover_fields.py --apply` to auto-populate |
| `issue_types` | No | `{}` | Maps issue type names to Jira issue type IDs. Run `discover_fields.py --apply` to auto-populate |

## Credential resolution order

1. If `env_file` is set, load variables from that file first
2. Then check OS environment variables
3. The variable names are taken from `credentials.username_env` and `credentials.token_env`

## Auto-discovery

Run the discovery script to auto-populate `field_mappings` and `issue_types`:

```bash
.jira-venv/bin/python <skill_dir>/scripts/discover_fields.py --config .jira.json --apply
```

This calls Jira's REST API to detect custom field IDs and available issue types, then updates `.jira.json` in-place.

## Manifest format

The manifest (`.jira-manifest.json`) is auto-generated and tracks created tickets for idempotent resume:

```json
{
  "epic": {
    "key": "API-8291",
    "summary": "My Epic"
  },
  "stories": {
    "1": {
      "key": "API-8301",
      "summary": "Foundation",
      "story_points": 2.0
    }
  },
  "subtasks": {
    "1.1": {
      "key": "API-8310",
      "summary": "Setup Environment",
      "parent_key": "API-8301",
      "story_points": 0.5
    }
  }
}
```

Do not edit this file manually — the scripts maintain it automatically.
